# [BUG-001] Master Prompt: Performance-Optimized Seek, Hover Preview & Unified Loading

**Context:** We are fixing the arrow-key seek stalls, implementing a lightweight hover-preview system, and ensuring the initial loading UI is non-blocking and flicker-free in both Preview and Standalone modes.

Please implement the following optimizations into our `media_kit` architecture:

## 1. "Sliding Window" Seek Logic (Arrow Keys)

* **Arrow Keys (Zero-Latency):**
* Configure the player to maintain a buffer of **60 seconds ahead** and **30 seconds behind** the current playhead.
* For `ArrowLeft` and `ArrowRight` (10s jumps), use `fast: true` seeking. Since this data is held in the "Sliding Window" cache, the jump must be instantaneous without triggering a loading state.


* **Manual Scrubbing (Standard Load):**
* For active dragging or direct clicks on the progress bar, allow standard high-precision seeking (`hr-seek: yes`).
* The `BubbleLoader` is permitted here if the data exceeds the cache, but use a **200ms "Smart Delay"** before showing it to avoid flickering during minor buffering.



## 2. Background Thumbnail Preview (Hover)

* **Requirement:** Display a small, low-resolution thumbnail in a frosted-glass popup above the progress bar during mouse hover.
* **Implementation:**
* Initialize a **secondary, headless `Player` instance** strictly for thumbnail generation.
* Set this instance to a low-bitrate profile to prioritize frame extraction speed over visual quality.
* **Throttling:** Only update the thumbnail every **150ms to 200ms** of mouse movement to protect CPU/GPU cycles from "seek flooding."



## 3. Unified Initialization UI (Preview & Standalone)

* **Problem:** The loader freezes during engine startup or shows a black screen in standalone mode.
* **Solution:** Implement a **Deferred Engine Warm-up**.
* **Step 1 (UI First):** Immediately render the `BubbleLoader` widget using a `Linear` animation curve.
* **Step 2 (Engine Second):** Only after the loader is rendered and animating, call `player.open()`.
* **Standalone Reveal:** For new windows, launch with **opacity 0.0**. Use `WidgetsBinding.instance.addPostFrameCallback` to call `window.setOpacity(1.0)` only after the first frame of the loader is committed to the GPU.
* **Transition:** Once the first video frame is ready, cross-fade from the `BubbleLoader` to the video surface using a **300ms `AnimatedOpacity**`.



## 4. Resource Allocation (Ryzen/Linux Optimized)

* **Native libmpv Configuration:**
* `demuxer-readahead-secs: 60`: Pre-buffers future video.
* `demuxer-max-bytes: 400MiB` / `demuxer-max-back-bytes: 200MiB`: Efficient RAM usage for the "Sliding Window."
* `vd-lavc-fast: yes`: Speeds up decoding for seeks.
* `hwdec: auto-safe`: Utilizes the Ryzen GPU to keep the UI thread light.
* `cache-pause: no`: Prevents UI lockup during background seeking.



## Architectural Requirements

* **Component Isolation:** Wrap the `Video` surface and the `BubbleLoader` in their own `RepaintBoundary` widgets to isolate native rendering from animations.
* **State Management:** Use a dedicated `VideoLoadingState` provider (Riverpod) to track transitions (`initializing -> buffering -> playing`) and keep the UI in sync across both window modes.
* **Hover Optimization:** The `HoverPreview` must be its own `StatefulWidget` to ensure thumbnail updates do not trigger rebuilds of the main player or sidebar.
