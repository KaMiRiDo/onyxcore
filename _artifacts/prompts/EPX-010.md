# [EPX-010] Master Prompt: Custom Desktop File Picker Implementation

**Context:** We are deprecating standard platform file pickers (e.g., GNOME Nautilus, Windows Explorer) to maintain a 100% cohesive UI and cross-platform parity. We are building a custom `CustomFilePickerDialog` entirely in Flutter. 

**Strict Constraints:**
1. **NO PLATFORM PACKAGES:** Do NOT use `file_picker`, `file_selector`, or any platform channel file dialogs.
2. **STRICT ABSTRACTION:** You MUST use the `FileSystemService` (which uses the `file` package) to read directories and files. Do NOT use `dart:io` `File` or `Directory` directly in the UI or State layers.

Please implement the custom file picker with the following architecture:

## 1. State Management (`FilePickerNotifier`)
Create a state controller for the file picker. It must manage:
- `currentDirectory`: The current path being viewed (default to `~` / user home directory).
- `showHiddenFiles`: Boolean (default: `false`).
- `contents`: List of `FileSystemEntity` (Directories first, then Files, alphabetically sorted).
- **Navigation Logic:** - `goToDirectory(String path)`: Update path and reload contents.
  - `goUp()`: Navigate to the parent directory.
- **Exception Handling:** Wrap directory reading in a `try-catch`. If a `FileSystemException` is caught (e.g., Access Denied to `/root`), catch it silently, revert to the previous directory, and emit an error state/snackbar message to the UI.

## 2. UI Architecture (The Dialog Layout)
Create `CustomFilePickerDialog` as a stateful widget that returns a selected `File` or `null`.
- **Styling:** Use a `Dialog` with a frosted-glass `BackdropFilter` background. Ensure all typography uses the 'Outfit' font family.
- **Layout Structure:** A split-pane design.
  - **Left Sidebar (Width: 200px):** Quick navigation links. Include hardcoded paths to the user's Home, Documents, Downloads, and Videos directories.
  - **Top Bar:** A breadcrumb trail of the `currentDirectory`, an "Up" arrow button, and a toggle switch for "Show Hidden Files".
  - **Main Content Area:** A `GridView` or `ListView` rendering the `contents`.

## 3. Entity Rendering & Interaction (`FileEntityTile`)
- **Visuals:** - Directories: Use a standard folder icon.
  - Files: Use a standard file/video icon. ( icons and all can be used from the current implementation of folders and files items)
- **Interactions:**
  - **Single Click on Directory:** Highlight the folder
  - **Double Click on Directory:** Trigger `goToDirectory()`.
  - **Single Click on File:** Highlight as "Selected". Update the bottom "Confirm" button.
  - **Multiple Selection:** user could be able to select mutiple files with Ctrl click and shift click options 
  - **Double Click on File:** Select the file and instantly `Navigator.pop(context, selectedFile)`.

## 4. Execution & Bottom Bar
- The bottom of the dialog must have a "Cancel" button (`Navigator.pop(context, null)`) and an "Open" button (enabled only when a file is selected).

Please generate the necessary State and UI files to implement this architecture.
